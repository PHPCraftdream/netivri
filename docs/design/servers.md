# Servers: netivri as an entry point

Status: design. Tracks the work of the `servers` series of changes.

## Goal

Today netivri is a client side: apps connect to its local port (SOCKS5, SOCKS4
or HTTP), and their traffic leaves through the route of the account that
logged in. A **server** makes the same routes reachable from other machines
over a VPN-node protocol, so that one netivri on a VPS (or at home) is the
entry point for phones and laptops:

```text
phone (ss://, vless://, ...) -> netivri server -> account route -> [pre] -> node -> [post] -> destination
```

An account without a route leaves directly (or through its `post_socks5`), so
the same feature turns a VPS into a plain exit node.

Acceptance: `netivri server add` + `netivri server link` give a URI that a
stock client of that protocol accepts; the connection is counted and routed as
the owning account; a client address the account does not allow is dropped;
every protocol has a loopback test that drives it with the matching Mihomo
client adapter.

Non-goals (first versions): ACME / Let's Encrypt, an HTTP endpoint that serves
subscriptions, TUN, protocols that need a domain fronting service, a GUI.

## Building blocks already in the tree

- The vendored Mihomo has server listeners for Shadowsocks, VLESS (TLS, WS,
  gRPC, XHTTP, Reality), VMess, Trojan, Hysteria2, TUIC, AnyTLS, Snell, Mieru,
  Sudoku, ShadowQUIC, TrustTunnel and others (`third_party/mihomo/listener`).
  They take a `tunnel` (`C.Tunnel`) and `inbound.Addition` options.
- Accounts are routed by rules `IN-USER,<login>` (`internal/core/accounts.go`),
  and the sticky groups read `metadata.InUser`. A listener that sets `InUser` to
  the account login gets the account's route, statistics, hops and logging for
  free. The sticky group's `ListenPacketContext` chooses its sticky member;
  `SupportUDP` checks the first member and `IsL3Protocol` checks the selected
  member. An account rule that does not support UDP may be skipped, allowing a
  later `MATCH,DIRECT` rule to handle UDP. This version rejects server UDP to
  prevent traffic from bypassing the account route.
- VLESS, VMess and Trojan listeners take a user list and set `InUser` to the
  user's `Username`. Mihomo's Shadowsocks server has a single password, so it
  needs one listener per account, each started with `inbound.WithInUser(login)`.
  Protocols differ here, see the matrix.
- **The global IP filter does not cover these listeners.** Mihomo's `inbound.SetAllowedIPs` (`listen.allowed_clients`) is consulted by HTTP, SOCKS and mixed listeners, not the Shadowsocks server. Core therefore enforces the global and per-account allowlists in the wrapped tunnel before forwarding, using `metadata.SrcIP` and `metadata.InUser`. A nil policy pointer is unrestricted; with a configured policy, nil global/account slices mean unrestricted and empty non-nil slices deny all. VLESS Reality camouflage explicitly uses built-in `DIRECT`; its `INNER` metadata has no client IP or account and therefore bypasses these filters and client-route counters. Authenticated VLESS clients continue through normal account routing and policy enforcement.

## Model

- A **server** is one listening endpoint of one protocol: `name`, `protocol`,
  `bind`, `port`, the accounts it serves, `public_host` (for links) and
  protocol parameters.
- A protocol is **multi-user** (one listener serves many accounts, each with its
  own secret) or **single-user** (one listener per account, so the server names
  exactly one account). The protocol declares which.
- **Secrets are generated by netivri, never typed.** Account passwords are
  argon2id hashes and cannot key a server, so each (server, account) gets its
  own random secret (a key, a UUID or a password, as the protocol needs), and
  each server may have *material* (a Reality key pair and short ids, a TLS
  certificate). Both live in the secrets file, apart from `config.ktav`.

## Config

```text
servers: [
    {
        name: vps-ss
        protocol: shadowsocks
        bind: 0.0.0.0
        port: 8388
        accounts: alice
        public_host: vps.example.org
    }
]
```

- `name`: 1 to 32 characters of `A-Za-z0-9._-`, unique.
- `protocol`: a name from the registry (`netivri server protocols`).
- `bind`: default `0.0.0.0`; `doctor` warns that the port is public.
- `port`: 1 to 65535, required, unique per bind and transport.
- `accounts`: login list, or `*` for every account (multi-user protocols only; a single-user protocol needs exactly one resolved login). Core resolves `*` before creating a `Spec`; `Spec.Validate` accepts only resolved logins.
- `public_host`: host name or address carried by links; may be empty, then `server link --host` is required.
- unknown protocol parameter keys are `CONFIG_INVALID` and identify the key, never its value.
- `Spec.Validate` checks resolved names (`1..32` `A-Za-z0-9._-`), ports (`1..65535`), bind IP shape, unique logins (`1..64` `A-Za-z0-9._@-`, not `*`), protocol params, and the single-user account count. `ListenAddress()` supplies `0.0.0.0` for an empty bind.

## Secrets file

`{HOME}/server-secrets.ktav`, mode 0600, written atomically (temp file, fsync,
rename), read only by netivri:

```text
servers: {
    vps-ss: {
        material: { ... }
        users: { alice: { password: ... } }
    }
}
```

- `server add` generates what is missing; `server remove` deletes the entry;
  `server rotate NAME [--account A]` replaces the secret of a user (or the
  material) and reloads the running angel.
- Secrets are never printed except by `server link` (the URI is the point) and
  never written to a log, the state file, `status` or `--json` output of any
  other command.
- A config server without a secrets entry is repaired at `up`; a secrets entry
  without a config server is ignored and reported by `doctor`.

## Package layout

New package `internal/servers`, imported by `internal/core` and `cmd/netivri`:

```go
type Spec struct {
    Name, Protocol, Bind string
    Port                 int
    Accounts             []string
    Params               map[string]string
    Material             SecretMap
    Users                UserSecrets // login -> map[string]string
}

type Protocol interface {
    Name() string
    SingleUser() bool
    Validate(params map[string]string) error
    NewMaterial(params map[string]string) (map[string]string, error)
    NewSecret(login string, params map[string]string) (map[string]string, error)
    Start(spec Spec, env Env) (io.Closer, error)
    Link(spec Spec, login, host string) (string, error)
}
```

- `Env` carries `Tunnel C.Tunnel` and `ListenConfig C.InboundListenConfig` only. The registry API is `Register(Protocol)` (panics for duplicate names), `Lookup(string) (Protocol, bool)`, `Names() []string` (sorted), and `Registered() []Protocol` (sorted). `Spec` implements validation, redacted formatting, deep clone/equality, and `ListenAddress()` (empty bind becomes `0.0.0.0`). All maps are redacted in `Spec.String` / `GoString`. `NewMaterial` and `NewSecret` retain plain map return types.
- `Running` holds `Name, Protocol, Listen`, `Accounts` and `Closer`; `(*Running).Close()` is nil-safe. `Info` holds `Name, Protocol, Listen`, `Accounts`, `Connections int`, `DroppedClients uint64`. Optional `MihomoLinker` exposes `Mihomo(spec, login, host) (string, error)`.
- `NewSecret` returns fields in a regular map for assignment into `UserSecrets[login]`; `NewMaterial` returns fields for `Spec.Material`. Keep secrets out of logs, errors and status.
- Protocols register themselves in `init()` (`servers.Register`). A protocol
  change therefore touches only its own files: `internal/servers/<protocol>.go`,
  its tests and `docs/servers/<protocol>.md`. The CLI, `help` and the drift test
  read the registry, so a new protocol appears everywhere without further edits.
- `Link` returns the client URI of the protocol, or, for protocols without a
  standard URI (Snell, Mieru, Sudoku, ShadowQUIC, TrustTunnel), a Mihomo proxy
  snippet; `server link --format uri|mihomo` picks.
- TLS-based protocols share a helper: a self-signed ECDSA P-256 certificate for
  the public host with its SHA-256 fingerprint (pinned in links), or the user's
  `cert_file` / `key_file`. There is no ACME.

## Core wiring

- `core.Options.Servers []servers.Spec`. `Start` stages listeners through the core socket broker and commits them transactionally; unchanged specs keep their listener and connections. A changed listener stops accepting new connections after commit, while tracked connections drain until `Instance.Close`. A failed stage rolls back and retains old entries.
- An address in use is `PORT_IN_USE`, as for the mixed listener; a server that
  fails to start fails `up` (fail closed), a reload that fails keeps the old
  servers and reports the error.
- Every listener gets a wrapped tunnel that (1) drops a client that
  `listen.allowed_clients` or the account's `allowed_clients` does not allow,
  counting the drops, and (2) otherwise passes through to the normal tunnel,
  where rules, sticky groups, hops and `OnConnEvent` apply unchanged.
- UDP: the core tunnel wrapper drops and counts UDP traffic arriving through all server tunnels. Shadowsocks currently exposes TCP only; UDP is unsupported for this version.

## UDP-bound servers

- A protocol may optionally implement `UDPBound() bool`. Protocols implementing `UDPBound() bool` as true use `Env.ListenConfig`'s real UDP socket through Mihomo `inbound.ListenConfig`; TCP `Listen` on that endpoint is rejected. UDP listeners are closed synchronously so the UDP port is free when `Close` returns.
- Reconfiguration commits TCP changes, then restarts every changed or removed UDP-bound listener. UDP sockets cannot be handed over: QUIC owns packet-connection and session state. The restart has a brief gap and existing connections end.
- If reconfiguration fails, rollback restores TCP leases and best-effort restores all prior UDP specs. The result reports whether UDP restoration completed or was incomplete.
- Port conflicts are checked per transport, so TCP and UDP may share a bind and port. Counters are shared across generations of a server name. UDP relay traffic is still dropped and counted; UDP-bound only describes the listener transport.

## One port, several protocols (design, not implemented)

Goal: several servers on one TCP port, the protocol chosen from what the client
sends. Already true today: TCP and UDP are separate port spaces and conflicts are
checked per transport, so one TCP server and one QUIC server may share a number
(443/tcp Trojan or Reality plus 443/udp Hysteria2 or TUIC). The rest needs a
front mux for servers of the same transport.

**Where it plugs in.** `internal/core/servers_broker.go` already owns the real
socket (`socketEndpoint`, one `acceptPump`) and hands every accepted connection to
the single active lease of the endpoint; protocols only see a `net.Listener`. The
mux keeps that shape: an endpoint may hold one active lease per server plus a
classifier; the pump classifies each connection and sends it to exactly one lease.
Protocols do not change. A server joins a shared endpoint only if its protocol
implements an optional `Sniffer` (a pure function over the peeked bytes), so
protocols without one keep exclusive ports.

**Classification pipeline** (per connection, first-byte deadline of a few seconds,
nothing is consumed: the peeked bytes are replayed to the chosen server):

1. TLS ClientHello (`0x16 0x03`): parse SNI and ALPN. A server matches by its
   `sni` parameter (Reality: its `ServerNames`) and its ALPN set (TrustTunnel: `h2`).
   Two TLS servers with the same SNI and ALPN cannot be told apart before the
   handshake is decrypted (Trojan sends 56 hex characters and CRLF first, AnyTLS 32
   binary bytes, both inside TLS), so `server add` refuses the combination
   (`SERVER_PORT_AMBIGUOUS`, hint: give one of them another `sni`). One TLS server may
   be marked the default for a ClientHello that matches no SNI; without a default the
   connection is closed.
2. Not TLS: protocols with no cleartext marker (Shadowsocks, VMess, Snell, Sudoku,
   Mieru) can only be told apart by trial authentication of the first bytes (AEAD
   length block, VMess auth id inside its time window). Stage 2 allows a short
   whitelist of such protocols per port, tries them in a fixed order, and closes the
   connection when none accepts. The cost is a few cheap operations per connection;
   the risk is that the time to reject differs from a plain server (active probing),
   so a rejected connection is closed after a fixed minimum delay.
3. QUIC (UDP): servers on one UDP port are told apart only by the ALPN in the QUIC
   Initial, which Hysteria2, TUIC and ShadowQUIC mostly share (`h3`): the combination
   is refused unless the ALPN sets differ.

**Config and CLI.** `server add --port N` with an existing server on N (same
transport) succeeds only when the combination is classifiable; otherwise it fails
with `SERVER_PORT_AMBIGUOUS` and a hint. `server list` and `status` show the
shared endpoint and its members; `doctor` reports sets that stopped being
classifiable (for example after a certificate or `sni` change). Per-server
counters stay per server; the mux adds `unclassified` (closed without a match).

**Stages.** (1) TLS family by SNI and ALPN, including Reality's own fallback to its
camouflage target for unauthenticated clients. (2) Trial authentication for
Shadowsocks and VMess. (3) QUIC ALPN where the sets are distinct.

**Tests.** Unit: the classifier over recorded first-byte fixtures of each protocol
(real ClientHellos with SNI and ALPN, a Shadowsocks AEAD first chunk, a VMess header,
garbage, an empty connection, a slow connection). Integration: two or three
protocols on one port reached by their real Mihomo clients, one reload that moves a
server in or out of the shared endpoint, a rollback. e2e: the CLI path with real
binaries.

**Security notes.** The close behavior of the mux must not reveal the set of
protocols (unmatched traffic ends like a plain server's); peeked bytes are never
logged; the peek buffer is bounded; a slowloris client is cut by the first-byte
deadline and counted.

**Non-goals now.** UDP relay, domain fronting, camouflage beyond Reality's own,
classification that needs terminating TLS in the front.

## CLI

```text
netivri server protocols [--json]
netivri server add --protocol P [--name N] --account A|* --port N [--bind ADDR]
                   [--public-host H] [--param key=value ...] [--json]
netivri server list [--json]
netivri server show NAME [--json]
netivri server link NAME [--account A] [--host H] [--format uri|mihomo] [--qr]
netivri server rotate NAME [--account A] [--json]
netivri server remove NAME [--json]
```

All take `--home` or `--local`. `add` generates secrets, writes the config and
reloads a running angel; without a name it makes one (`ss-8388`). Exit codes
follow `docs/cli.md`: usage 2, not found for an unknown server, conflict for a
taken name or port, `CONFIG_INVALID` for bad parameters.

`status` lists the servers (name, protocol, listen address, accounts, current
connections, dropped clients). `doctor` checks: secrets file mode, public bind,
port conflicts, certificate expiry, a server whose account no longer exists.

## Logs

One line per event, never a secret, an address or a site: `server vps-ss
(shadowsocks) listening on 0.0.0.0:8388 for account alice`, `server vps-ss
stopped`, `server vps-ss: 14 clients dropped by allowed_clients in the last
minute` (INFO, WARN from 100). Connections of a server go through the same
connection log as the local port, with the account as login.

## Security

- A public port is an authenticated proxy on the internet: secrets are random
  and long, comparison is the listener's own, nothing is logged on a failed
  handshake beyond a count, and protocols that resist active probing (Shadowsocks
  2022, Reality, Trojan fall-through) are preferred in docs.
- `allowed_clients` is enforced before routing, as above.
- `bind` defaults to public because that is the point of a server, and `doctor`
  says so; `--bind 127.0.0.1` keeps it local (the loopback tests use it).
- The secrets file is the only place with secrets; `--local` keeps it inside
  `./.netivri` with the rest.

## Protocol matrix

| Protocol | Users | TLS | Transport | Link |
| --- | --- | --- | --- | --- |
| shadowsocks (2022 and AEAD) | single | no | TCP only (UDP unsupported) | `ss://` |
| vless-reality | multi | Reality (no certificate) | TCP | `vless://` |
| vmess | multi | no (AEAD) | TCP | `vmess://` |
| trojan | multi | TLS material | TCP | `trojan://` |
| hysteria2 | multi | TLS material | QUIC (UDP) | `hysteria2://` |
| tuic | multi (per uuid) | TLS material | QUIC (UDP) | `tuic://` |
| anytls | multi | TLS material | TCP | `anytls://` |
| snell | single | no | TCP | Mihomo snippet |
| mieru | multi | no | TCP, UDP | Mihomo snippet |
| sudoku | single | no | TCP | Mihomo snippet |
| shadowquic | multi | TLS material | QUIC (UDP) | Mihomo snippet |
| trusttunnel | multi | TLS material | TCP | Mihomo snippet |

"multi or single" is the expected model; each protocol task verifies it against
the listener and falls back to one listener per account when the listener does
not name the user. A protocol that cannot be driven on loopback with its Mihomo
client adapter is reported, not shipped untested.

## Tests

- Unit: registry, config and secrets validation, link generation per protocol
  (round trip through the matching URI parser where one exists), the client
  filter.
- Integration, per protocol: the server in one `core.Start`, the matching Mihomo
  outbound adapter as the client, a node recorder as the account's node; checks:
  traffic follows the account's route, a wrong secret is refused, a disallowed
  client is dropped, `Reconfigure` with a rotated secret, `Close` frees the port.
- e2e: a netivri client reaches an echo backend through another netivri's
  server using the link as its subscription (Shadowsocks first, then one TLS and
  one QUIC protocol).
- A drift test: every registered protocol has `docs/servers/<protocol>.md`, an
  index row and a mention in the `server` help topic.

## Delivery

1. Foundation: package, registry, core wiring, client filter, Shadowsocks.
2. In parallel: product (config, secrets store, CLI, status, doctor, logs),
   VLESS Reality, VMess, the TLS material helper.
3. In parallel, after the helper: Trojan, Hysteria2, TUIC, AnyTLS, ShadowQUIC,
   TrustTunnel; and, after the foundation, Snell, Mieru, Sudoku.
4. Docs sweep: index, README, `cli.md`, `config.md`, help, changelog, one full
   CI run, a check on a real machine on a loopback bind.

## Open questions, settled by the first tasks

- Shadowsocks UDP is unsupported in this version. The core tunnel wrapper drops and counts UDP traffic through server tunnels.
- Safe same-address server changes are staged by the core socket broker. Unchanged specs retain their running listeners; committed changes stop new accepts on the old lease while existing tracked connections drain until `Instance.Close`.
- Whether the TUIC, AnyTLS, TrustTunnel and ShadowQUIC listeners carry the user
  name into `InUser` (otherwise one listener per account).
- The default Reality camouflage target (`www.microsoft.com:443`, must speak TLS
  1.3 and X25519; overridable by `dest` and `sni`).
