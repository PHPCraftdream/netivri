## Decisions
- Mihomo as an embedded Go library (own `mixed` listener with its own AuthStore, `executor.ApplyConfig` for proxies/rules) over a supervised subprocess or a fork; reason: pluggable `Authenticator` for the init/hash auth, adapter access for warm-up, one binary.
- Ktav 0.8.0 via the official `ktav-lang/golang` binding as is (user's call); the native library is fetched only at release build time with pinned SHA256, shipped next to the binary, and `KTAV_LIB_PATH` is set in-process so the binding never downloads at runtime (a hidden direct download would bypass the fetch-proxy rule).
- Config write-back by whole-file regeneration (`Dumps` + mandatory round-trip check, comments not preserved) instead of a comment-preserving text editor; the editor was too error-prone to write without running it.
- Tests and builds only in GitHub CI; scopes = package (area) x build tag (unit/integration/e2e/bench), per-package coverage floors in `scripts/coverage-min.txt`.
- Pre-dial pool research verdict: raw-TCP pool possible via `DialerForAPI`, TCP+TLS/REALITY pre-establishment needs a fork, fixed-destination parking of a finished tunnel is feasible via a wrapper adapter, retargeting a tunnel is impossible; v1 plan for #15 is probing and keep-warm without a fork.
