## Decisions
- Removed the single-country account routing from the core API in favour of opaque route keys (`RouteNodes`/`AccountRoute`) so that a route can be (provider, country) without the core knowing either; keys never reach a rule or a proxy name (internal names `netivri-r<R>-<N>`, groups `netivri-group-<R>`).
- A provider is a subscription record (`sub add <url>` authorises by the link and stores the record and node snapshot); no new `provider` command group, the CLI keeps `sub`. `sub countries` has three forms (stored provider, all providers, `--url` fetch-only). Bound providers cannot be removed (`SUB_IN_USE`).
- Installers: rename-aside replacement (always on Windows, atomic mv on POSIX), never stop the daemon, print a restart hint; `--from-dir` accepts both layouts and skips the checksum (npm integrity covers that path); `--quiet` silences everything but errors. The future npm installer is documented as calling `install.sh --from-dir <platform pkg> --dir <stable dir> --quiet`.
- `drainFinalizers` now follows finalizer chains in up to four rounds under one 2 s deadline (a proxy group holds adapters with their own finalizers), instead of dropping `-race` or the drain.
- Daemon status prints the LIVE answer of the control server; the state file token never leaves the machine; foreground `up` writes nothing to stderr; only the daemon child logs to `run/netivri.log`.
